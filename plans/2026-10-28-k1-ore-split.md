# K=1 OreSplit: LLM MARL Pipeline on Factoriax — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two LLM agents each write one plan in text. Factoriax executes both plans in a single jitted rollout and returns a shared team reward, and MAGRPO trains LoRA adapters on that reward. Training can be stopped and resumed across paid A100 sessions.

**Architecture:** This is the K=1 case, so each agent makes one decision per episode. Each agent emits `BUILD <patch> <count>` lines. A host-side compiler turns them into a fixed-length primitive-action array per player, and `jax.lax.scan` runs both players at the same time through a new multi-player step. The task, OreSplit, scores `min(iron, copper)` delivered to pallets. Neither agent can score alone, so division of labour is necessary. The Factoriax-side code lives in a new `factoriax/marl/` subpackage with no engine edits. The training glue (CoMLRL, PEFT, checkpointing) lives in `experiments/k1/` and is not packaged.

**Tech Stack:** JAX + Factoriax (this repo), Python 3.11+, CoMLRL (MAGRPO), Hugging Face `transformers` + `peft`, PyTorch, Colab / A100.

**Spec:** Conversation of 2026-10-28 (K=1 design, CoMLRL findings, checkpointing requirements); research framing in `plans/2026-10-28-research-plan-probe-framing.md`.

**Commits:** Do not commit. Brendan will commit when ready.

## Global Constraints

- No edits to `factoriax/engine/`. Everything new goes in `factoriax/marl/`, `experiments/k1/`, `tests/marl/`.
- The rollout must compile once. Action arrays are always `(HORIZON, NUM_PLAYERS)` int32, padded with `Action.NOOP`.
- `HORIZON = 400`, `NUM_PLAYERS = 2`. Each player starts with 4 `MINER` and 4 `PALLET`.
- The team reward is `min(iron_ore_in_pallets, copper_ore_in_pallets)`, normalised by the oracle score of that variant. An unparseable agent output costs `-0.1` per agent.
- Same plans + same variant → same score (determinism is required for GRPO and resume).
- Training dependencies (`comlrl`, `peft`, `transformers`, `torch`) stay out of `pyproject.toml`. They go in `experiments/k1/requirements.txt`, with CoMLRL pinned to an exact git commit, because `ResumableMAGRPO` uses private CoMLRL methods.
- Checkpoints hold LoRA adapters + optimiser state + RNG + `global_step` only, never the full base weights.
- Test command for the package side: `uv run pytest tests/marl -v`. Lint: `uv run ruff check factoriax tests experiments`.

## Review Focus

1. **LLM output wrapped in prose, markdown, or code fences.** The parser must still find the `BUILD` lines → `test_parse_ignores_surrounding_text` (Task 4).
2. **A count above the inventory, zero, or negative, or an unknown patch name.** Clamp or drop, never raise → `test_parse_clamps_and_drops` (Task 4).
3. **Both agents pick the same patch.** The second placement on a taken site fails silently, the rollout completes, and the score is lower but valid → `test_same_patch_collision_scores_lower` (Task 5).
4. **Plans longer than the horizon.** Truncate to `HORIZON`, never error → `test_compile_truncates_to_horizon` (Task 3).
5. **Retracing.** A new plan must not trigger a recompile (a 50 s cliff on CPU) → `test_rollout_compiles_once` (Task 5).

### Task 3: Macro compiler

**Files:**
- Create: `factoriax/marl/macros.py`
- Test: `tests/marl/test_macros.py`

**Interfaces:**
- Consumes: `sites()`, `spawns()`, `make_level()`, `HORIZON` from Task 2.
- Produces:
  - `Macro(NamedTuple): patch: str; count: int`
  - `compile_plan(macros: Sequence[Macro], player_idx: int, variant: int) -> np.ndarray` returns shape `(HORIZON,)` int32, NOOP-padded.
  - `compile_joint(plans: Sequence[Sequence[Macro]], variant: int) -> np.ndarray` returns shape `(HORIZON, NUM_PLAYERS)`.

Rules:
- A player builds at the first `count` sites of the named patch, in table order. Both players use the same order, so a duplicated patch causes a collision. That's intended: interference is a coordination signal.
- Per site: path to `miner`, `FACE_<facing>`, `PLACE_PALLET`, one move against `facing` to `stand`, `FACE_<facing>`, `PLACE_MINER`.
- Paths are BFS over the static level, treating every site's `miner` and `pallet` tiles as blocked (except the target `miner` tile), so routes never run through machines that will be placed later.
- The total miners and pallets used across all macros is capped at 4 each (the inventory). Macros past the cap are dropped.
- Anything beyond `HORIZON` is truncated.
